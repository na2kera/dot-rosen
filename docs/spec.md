# ドット路線メーカー（仮） 仕様

2026-11-20 の聞き取りで決めた内容。実装はこの文書を正とする。変更したらここも直す。

## 1. 概要

- 首都圏の実在駅を選んで自分だけの路線を作り、電車の外観と路線名を決める Web アプリ。
- 全体をドット絵調にする。
- 作った路線を、主催者が持つ感熱プリンタで「路線カード」として印刷して渡せる。
- スマホで使う人が多い前提で作る（スマホ対応必須）。

## 2. 利用シーン

- 普段は誰でも遊べる公開 Web。イベント時だけ会場のプリンタで印刷できる。
- 最初に仕上げるのは「会場で作って印刷を受け取る」体験。公開 Web 側は「作って画像で保存」まで。
- 締切なし、品質優先。

## 3. 印刷

### プリンタ

- M5Stack ATOM Printer 感熱プリンタキット（K118）。ATOM Lite（ESP32-PICO-D4）付属。
- 紙幅 58mm、1行 384 ドット、203dpi、白黒2値、手でちぎる方式。DC 12V / 2.5A。
- 標準ファームは画像を印刷できないので、ファームを自作する。
- 参考: https://github.com/m5stack/ATOM-PRINTER （MIT。命令一覧 `ATOM_PRINTER_CMD.h`、ピン割り当て、`PRINTER_IMAGE` サンプル）

### 経路

- 来場者のスマホ → サーバー → ATOM Lite（Wi-Fi）→ プリンタ。
- ATOM Lite は3秒おきにサーバーへ「次の印刷はあるか」と問い合わせる。あれば画像を数十行ずつ小分けに取りに行って印刷し、完了か失敗を報告する（メモリが小さく転送も遅いため、一度に全部は受け取らない）。
- 途中で失敗した印刷は自動では刷り直さない。主催者が管理画面で再印刷する。
- 予備として、USB でつないだ PC からも同じデータを受け取れるようにする。
- サーバーは合い言葉（機器用トークン）を持つ機器にだけ印刷データを渡す。
- 会場の回線は主催者のテザリングかモバイルルーターを使う。

### 印刷できる人の制限

- 会場に掲示した QR コード（会場コード）から開いた人にだけ印刷ボタンが出る。印刷は自動。
  - 会場コードなしで開いた人には、印刷の欄に「印刷は イベント会場で できます。会場の QR コードを 読みこんでね」と案内を出す（Issue #2）。
  - 主催者が自分の端末で試すときは、管理画面の「会場コード」タブの「この端末でひらく」から開く。
- 1台の端末につき印刷は1回まで。刷り直しは主催者が管理画面から許可する。
- 来場者の画面に「あと何人待ち」を表示する（5秒おきの問い合わせで更新）。
- 待ちは同時に 30 件まで。超えたら申し込みを断り、少し待ってもらう。
- 回数の制限は端末のデータを消せば回避できる、ゆるいもの。
- 会場コードは作り直せる。作り直すと古いものは無効になる。

### 印刷の見た目の決め方

- 模様（`light` / `bold`）と側面の置き方（`two-x1` / `lead-x2` / `two-x2-rotated`）は、管理画面の再印刷で刷り比べて決め、決めた値を `wrangler.jsonc` の vars（`CARD_MONO_SET`・`CARD_SIDE_LAYOUT`）に入れる。

### 印刷画像の作り方

- 画像はサーバーが路線データから組み立てる。スマホから画像そのものは受け取らない（任意の画像を印刷させないため）。
- 画像を組み立てるプログラムは1つだけ書き、スマホの印刷プレビューとサーバーの両方で同じものを動かす。出力は1ドット単位で一致させる。
- 文字はブラウザに描かせず、フォントをあらかじめ点のデータに変換したものを直接並べる。

### 路線カードの中身（上から順）

1. 見出し: ロゴ、路線記号、路線名（大きな文字）
2. 区間: 「始発駅 ⇄ 終点駅」。環状線のときは「環状」
3. 正面の顔を大きく1つ
4. 側面の絵: 先頭から2両。下に「◯両編成」（1両編成は1両だけ）
5. 停車駅案内: 縦の線に沿って、駅ナンバリングと駅名を1駅1行
6. データ欄: 駅数、総距離（駅間の直線距離の合計。「直線距離」と添える）、発行日、発行番号（No.0042 のような通し番号）
7. QR コード（路線ページの URL）とアプリ名

- 所要時間は載せない。
- シール紙への駅名標印刷は、路線カードが動いたあとの追加メニュー。

### 実機でしか分からない点（未検証）

- プリンタとの通信速度を 9600bps から 115200bps に上げられるか。
- 黒い面積が多い画像を続けて印刷しても問題ないか。
- 紙切れを検知できるか。
- 結果によって、駅数の上限や停車駅案内の組み方を見直す。

## 4. 作る手順

4ステップ。画面下の切り替えでいつでも行き来できる。

1. 駅をえらぶ
2. 路線をきめる
3. 電車をつくる
4. できあがり（路線カードの確認、保存、画像保存、印刷の申し込み）

- どのステップにも初期値を入れておく。駅を2つ選ぶだけで「できあがり」まで進める。
- 「できあがり」に進めないのは、駅が2つ未満のときだけ。

## 5. 駅をえらぶ

- 範囲は1都3県（東京・神奈川・埼玉・千葉）。国の集計では 1,734 駅（改札内で乗り換えられる駅を1駅と数えた値）。
- 乗換駅は1つにまとめる（例: 新宿は会社を問わず1駅）。
- データは国土数値情報「鉄道データ」（国土交通省、CC BY 4.0）。アプリ内に出典を表記する。
- 地図は実際の位置どおりに駅を点で置いたドット絵の地図。指で動かし、2本指で拡大・縮小する。
  - 実在の路線を薄い灰色の線で下に描く（鉄道会社の公式色は使わない）。
  - 海岸線と大きな川を簡単に描く。
  - 引いた状態では駅は点だけ、拡大すると駅名を出す。
  - 駅名で検索でき、選ぶとその駅まで地図が移動する。
- 駅をタップした順に線がつながり、それが停車順になる。線路のない駅同士も直線でつなげる。
  - 1つ戻す。
  - 駅の一覧で並べ替えと削除ができる。
  - 一覧で「この駅の次に追加」を選んでから地図をタップすると、途中に駅を入れられる。
- 環状線は作れる（最後に始発駅をもう一度タップ）。分岐は作れない。
- 同じ駅は1回だけ（環状を閉じる始発駅は例外）。路線に入っている駅をタップしたら、外すかどうかを尋ねる。
- 1人が作れる路線は1本。
- 駅数は2以上30以下。「あと◯駅追加できます」を表示する。

## 6. 路線をきめる

- 路線名: 自由入力、12文字まで。「線」は自動で付けない。
- ラインカラー: 12色のパレットから1色。地図の線と停車駅案内の線の色。初期値は帯の色。
- 路線記号: 英字1〜2文字。
- 駅ナンバリング: 路線記号＋通し番号を自動で振る（例: KR01）。

## 7. 電車をつくる

### 方式

- 車体はパーツ選択式。ロゴだけ自由描画。
- 視点は「正面の顔」と「真横からの編成」の2つ。エディタでは並べて見せる。
- ランダムボタン: 押すと顔・側面・色・帯の選択がまとめてランダムに入れ替わる。確定はせず、そこから調整できる。何度でも押せる。

### 正面の顔（部位を重ねる）

| 部位 | 候補 |
|---|---|
| 輪郭 | 四角、角丸、上すぼまり、丸 |
| 前面窓 | 1枚の大窓、2枚窓、3枚窓、曲面のパノラマ窓、小窓 |
| 貫通扉 | なし、中央、片側寄せ |
| ライトの形 | 丸形、角形、横長の LED 風 |
| ライトの位置 | 窓の上、窓の下の両脇、腰の低い位置 |
| 行先表示 | なし、上部、窓の中 |
| スカート | なし、小、大 |
| 前面の塗り分け | 車体色のまま、窓まわりを黒、帯を回す、警戒色のしま模様 |

### 側面

| 部位 | 候補 |
|---|---|
| 鼻先 | 切妻（垂直）、ゆるい傾斜、丸み、流線形、ロングノーズ、ボンネット型 |
| 窓 | 四角い大窓、小窓が並ぶ、丸窓、横長の連続窓 |
| ドア | 片側2ドア、3ドア、4ドア |
| 屋根の機器 | パンタグラフのみ、クーラー付き、なし |
| 車体の色 | 12色から1色 |
| 帯・柄 | 帯なし、1本帯、2本帯、斜めストライプ、ドット柄、上下塗り分け（帯の色も選ぶ） |

### 絵柄（2026-11-20 にユーザーが了承）

- 基準は `prototypes/art-sample/v2-realistic.cjs` と `v2_color.png`（リアル寄り）。`v1` は不採用の比較用。
- 側面は1両 192×64 ドット前後。2両を横に並べると 384 ドット。正面の顔は 64×76 ドット前後。
- 実車（20m 級）の寸法比に合わせる。車体色ごとに明・基本・暗の3階調。
- ワイパー、手すり、クーラー、パンタグラフ、床下機器、台車などの細部を描く。
- 特定の実在車両の塗装やロゴの模写はしない。
- 印刷版（白黒）の模様と、側面の印刷倍率（等倍で横置き / 2倍で紙の長さ方向に寝かせる）は未決定。実機で刷り比べて決める。

### 両数

- 1〜16両、初期値8両。
- 編成は自動で組む（先頭車、同じ見た目の中間車の繰り返し、最後尾は先頭車の左右反転）。
- 画面では編成全体を横スクロールで見せる。

### ロゴ

- 16×16 ドット、2色（地の色と描く色。12色のパレットから）。
- 道具はペン、消しゴム、塗りつぶし、1つ戻す。
- 既製ロゴを12種類ほど用意する。選んでから描き足せる（今のロゴを下絵にして「じぶんで描く」）。
- 使う場所: 車体の側面、路線カードの見出し、駅選択画面で自分の路線を示す印。

### 「電車をつくる」の画面の配置（2026-11-21 に決定）

実機で触って出た指摘（ロゴのタブで、スクロール中に描いてしまう。既製ロゴが下にありすぎる。上のプレビューが大きく、操作する場所が小さい）を受けて決めた。

- **上のプレビュー**: 顔と編成を横に並べて 1 段にまとめ、いつも小さく表示する（ドット絵がにじまない整数倍）。その下に「ランダム」「1つ戻す」の 2 つを細い 1 行で置く。
  - 「◯両編成・横にスクロールできます」の行は置かない（両数は見出しに出ている）。編成の右端を少しぼかして、続きがあることを示す。
  - プレビューをタップすると「大きく見る画面」が開く（虫めがねの印を付ける）。顔を大きく、編成の全体を横スクロールで見せる。「カラー／印刷プレビュー」の切り替えはこの画面に置き、「できあがり」の切り替えと見た目をそろえる。「とじる」で戻る。
- **パーツの選択肢**: 5 列にして、1 つのパーツを 1 段に収める（6 つあるものだけ 2 段）。絵（サムネイル）の大きさは変えない。長い名前は 2 行までに収まる短い名前にする。
- **ロゴのタブ**: いちばん上に既製ロゴ 12 個を並べ、タップで選ぶ。その下に「じぶんで描く」ボタンを置く。タブの中には描く場所を置かない（スクロール中に誤って描かないため）。
  - 「じぶんで描く」を押すと、描くための画面が下からせり上がる。描く場所・道具（ペン、けしゴム、ぬりつぶし）・「1つ戻す」「ぜんぶ消す」・色の選択はこの中に入れ、スクロールせずに使える大きさにする。電車に付けたときの見え方を小さく出す。
  - 閉じ方は「できた」（電車に反映して閉じる）と「やめる」（開く前のロゴに戻して閉じる）。
  - 「できた」で描いたロゴは「じぶんの」として一覧の先頭に 1 つ残す。既製ロゴを選んだあとでも「じぶんの」をタップすれば戻せる。「じぶんで描く」は、「じぶんの」があればその続きから、なければ今のロゴを下絵にして始める。残すのは 1 つだけで、端末の中だけに覚える（保存する路線データの形は変えない）。

### 色の印刷表現

- 12色それぞれに、白黒の模様（白、黒、点、しまなど）をあらかじめ割り当てる。
- エディタに「印刷プレビュー」の切り替えを付ける（「大きく見る画面」の中に置く）。
- 印刷はドット絵を整数倍に拡大し、ぼかさない。

## 8. 見た目

- 明るいレトロゲーム風（白やクリーム色の地、色数を絞った配色、角ばった枠やボタン）。
- 画面上部の見出しだけ、駅の発車案内板風（黒地に光る点）。
- フォントは画面・印刷とも DotGothic16（SIL OFL）。入っていない字だけ JFドット jiskan16s で補う。
- 文字の大きさは16ドットの整数倍のみ。

## 9. 保存と共有

- アカウントなし。
- 作っている途中は端末の中に自動保存する。
- 「完成」か印刷の申し込みでサーバーに保存し、推測できない URL を発行する。
- 編集できるのは作った端末だけ（端末に鍵を持たせる）。URL を開いた他の人は見るだけ。
- 保存の前に「この URL を知っている人は誰でも見られます」と表示する。
- 作った端末からは、路線を消すこともできる。
- 画像として保存するボタンを付ける。画像は端末の中で作り、サーバーを通さない。
- 公開ギャラリーは作らない。
- サーバーが持つのは路線のデータだけ（駅、パーツの番号、ロゴの点、路線名など）。画像は保存しない。印刷用の画像は申し込み時に組み立て、印刷が終わったら消す。
- 有効期限は設けない（2026-11-20、Issue #1 で廃止。当初は保存から 30 日だった）。路線 1 件は 2〜3KB で容量の心配がなく、印刷した路線カードの QR コードがずっと開けるほうを優先した。
  - 期限の案内と、路線カードの期限の印字は無くす。
  - 残したくない路線は、作った端末から消せる（路線ページと「できあがり」の両方）。不適切なものは主催者が管理画面で非公開にする。

## 10. 不適切な入力への対応

- 禁止語チェックはしない。
- 管理画面から路線を非公開にできる。
- 作成画面に「実在の会社のロゴや名称をそのまま使わないでください」と1行入れる。

## 11. 管理画面

- 管理用パスワード1つで保護する。パスワードはサーバーの秘密の設定値。スマホで使う前提。
- 機能: 印刷待ちの一覧 / 取り消し / 再印刷 / 回数上限の解除 / 受付の一時停止と再開 / 会場コードの作り直し（QR コード表示）/ 路線の非公開化 / プリンタの状態（最後に問い合わせが来た時刻）

## 12. 技術構成

- 画面: Vite + React + TypeScript。地図と電車は Canvas 2D に直接描く。ゲームエンジンは使わない。
- サーバー: Cloudflare Workers + D1。
- ファーム: PlatformIO + Arduino（C++）。`firmware/` に置く。公式ライブラリの画像印刷は使わず、命令を直接送る。本体 LED の色で状態を示す。
- Wi-Fi の設定、サーバーの URL、機器用トークン、管理用パスワードはリポジトリに含めない。

## 13. 進め方

- 設計は Claude（Fable）が作り、Codex がレビューする。
- 実装（コードとドット絵素材）は Claude（Opus）が行い、Fable と Codex が適宜レビューする。
- 見た目と仕様の判断、実機確認はユーザー。
- ドット絵は、少数を作ってユーザーの了承を得てから量産する。素材はあとから差し替えられる形式にする。

## 14. 実装時に決めたこと（2026-11-20。ユーザーの確認待ち）

聞き取りで決めていなかった点を、実装中に仮で決めたもの。変えたい場合はここを直してから実装を直す。

### 駅と地図

- 駅は、同じ名前で互いに 600m 以内にあるものを1駅にまとめる。結果は 1,564 駅（国の集計 1,734 駅より少ない。会社が違っても同名で近ければまとめるため）。
- 名前が違う乗換駅（溝の口と武蔵溝ノ口など）は別の駅のまま。
- 川は描いていない。使えるライセンスのデータ（Natural Earth）では粗すぎたため。国土数値情報の河川・海岸線は非商用限定なので使わない。
- 駅の検索は駅名の文字だけ（データに読みがなが無い）。
- 密集した場所では、いちばん近い駅がほかより 8px 以上近ければその駅を選び、そうでなければその場所へ拡大する。

### 電車

- ランダムボタンは、顔・側面・車体色・帯色を変える。両数は変えない。ロゴは既製の中から選ぶ（自分で描いたロゴは残す）。
- ロゴは側面に 16×16 のまま貼る（先頭車と最後尾）。中間車には貼らない。
- パンタグラフは、1両編成は全車、2両は2両目、3両以上は先頭と最後尾を除いて2両目から3両おき。
- 12色の色味と、白黒の模様の割り当ては `shared/train/colors.ts` と `shared/train/mono.ts` で決めている。

### 保存・印刷

- 路線データの有効期限は、当初 30 日としたが、Issue #1 で廃止した。
- 待ちは同時に 30 件まで。回数制限（IP ごと）は、路線の作成が1時間に 120 回、会場コード違いが 10 分に 30 回、管理ログインの失敗が 10 分に 10 回。
- 来場者の画面は、待ちが 4 人以下なら 5 秒おき、5 人以上なら 15 秒おきに状態を問い合わせる。
- プリンタは 3 秒おきに問い合わせ、2 分間印刷が無ければ 10 秒おきに延ばす。
- 再印刷できるのは、完了か失敗の印刷だけ（取り消した印刷は不可）。
- Cloudflare Workers の無料枠（1回 CPU 10ms）に収めるため、起動時に路線カードを 8 回ためしに描いて温めている。
  - 2026-11-20 追記: Workers は有料プランになったので、この制限は当てはまらなくなった。温める処理は害がないので残している。

### そのほか

- アプリ名は仮に「ドット路線メーカー」。
- 公開先は `https://dot-rosen.na2kera.com`（独自ドメイン。2026-11-20 に設定）。`https://dot-rosen.na2kera.workers.dev` も残している。路線カードの QR コードと会場の QR コードには、そのとき開いていたドメインの URL が入るので、運用では独自ドメインのほうを使う。
- Hono（サーバーのルーティング）と qrcode-generator（QR コード）を依存に加えた。
